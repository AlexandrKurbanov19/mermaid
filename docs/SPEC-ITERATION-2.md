## 1. Ресёрч (факты, а не предположения)

### 1.1 Mermaid `timeline` — API проверен на `mermaid@12.2.0`

```
mermaid.mermaidAPI.getDiagramFromText(text).db
  db.getSections()  // ["2022","2023","2024"]
  db.getTasks()     // [{ id, section, type, task, score, events: string[] }]
```

Проверенные варианты синтаксиса:

| Вход | `getSections()` | `getTasks()` |
|---|---|---|
| `timeline\n 2022 : событие 1 : событие 2` | `[]` | `[{ section:"", task:"2022 ", events:["событие 1","событие 2"] }]` |
| `timeline\n title …\n section [Первый этап]\n 2022 : событие` | `["[Первый этап]"]` | `[{ section:"[Первый этап]", task:"2022 ", events:["событие"] }]` |
| `timeline\n section 2023\n Рост : Две новые программы` | `["2023"]` | `[{ section:"2023", task:"Рост ", events:["Две новые программы"] }]` |

Выводы для нормализации:
- **label точки** = `section`, если он непустой, иначе `task`;
- **title точки** = `task`, если `section` непустой (иначе пусто);
- `events` — детали под подписью;
- в текстах **хвостовые пробелы** (`"Рост "`, `"2022 "`) — обязательно `trim()`;
- `section [Имя]` приходит вместе со скобками — их надо срезать;
- **метода `getTitle()` нет** → заголовок `title …` берём регуляркой из исходного текста (у нас `normalize(db, source)` уже получает `source`).

### 1.2 Геометрия таймлайнов из архива (пиксельные замеры)

Инструментом-сканером по строкам (свой PNG-декодер):

| Слайд | Кружок ⌀ | Шаг между центрами | Заливка кружка | Ось |
|---|---|---|---|---|
| `image (6)` | **71 px** на слайде 960 px | **154 px** (≈ 2.17 ⌀) | `#E4E9EB` | `#E4E9EB` |
| `image (14)` | **114 px** на слайде 1668 px | **280 px** (≈ 2.46 ⌀) | `#BEF8EC`, активный — градиент `#6AEBC8→…` | `#E4E9EB` |

Что ещё видно на слайдах: подписи **чередуются сверху/снизу**, соединяются **пунктирной выноской с точкой** на конце; заголовок подписи — semibold, описание — вторичный цвет.

## 2. Изменения модели (DSL)

`DiagramIR` становится размеченным объединением. Это версия `v: 1` с новым полем `type`.

```ts
interface BaseIR {
  v: 1
  type: DiagramType                 // 'flowchart' | 'timeline'
  title?: string                    // из `title ...`
  warnings: string[]
}

interface FlowchartIR extends BaseIR {
  type: 'flowchart'
  direction: Direction
  nodes: IRNode[]
  edges: IREdge[]
  groups: IRGroup[]
}

interface TimelineIR extends BaseIR {
  type: 'timeline'
  points: TimelinePoint[]
  lanes: TimelineLane[]             // группы точек (из `section`)
}

interface TimelinePoint {
  id: string
  label: TextBlock                  // в кружке: «2022», «1», «Этап 1»
  title?: TextBlock                 // над/под кружком, semibold
  events: TextBlock[]               // детали под заголовком
  laneId?: string
}
interface TimelineLane { id: string; label?: TextBlock; pointIds: string[] }
```

Новые поля для flowchart-узла (для бейджей и ролей):

```ts
interface IRNode {
  …
  badge?: string                    // «1», «С» — выносится в кружок
  role: … | 'chevron' | 'secondary' // +2 роли
}
```

**Правило бейджа — без нового синтаксиса.** Если лейбл начинается с `N.` или `N)` + пробел
(`"1. Понять проблему"`, `"3) Критерии"`) — число выносится в кружок-бейдж, остальной текст остаётся в блоке.
Регулярка: `^(\d{1,3})[.)]\s+`. Не срабатывает на `1.5 млн` (нет пробела после точки) и на `2022 год`
(нет точки) — это важно, иначе даты в таймлайнах превращались бы в бейджи.

Роли:
- `chevron` — из mermaid `A>текст]` (сейчас сводится к `box`);
- `secondary` — маркер `:::secondary`, заливка `#DEE9FF` (это значение `--on-light-surface-accent-minor`
  из темы Plasma, которую использует DS; в архиве синий блок `#C2DCFE`).

## 3. Раскладка таймлайна (`layout/layoutTimeline.ts`)

Горизонтальная ось, точки равномерно, подписи чередуются.

```
        [2022]        [2024]        [2026]        ← подписи сверху (нечётные)
   ●———————○————————————○————————————○———●        ← ось
              [2023]        [2025]                 ← подписи снизу (чётные)
```

Параметры (в наших единицах, не в пикселях слайда):

| Параметр | Значение | Почему |
|---|---|---|
| диаметр кружка | `56` | в архиве ⌀ ≈ 2.2–2.5 шага; при шаге 180 это визуально то же |
| шаг между центрами | `180` | должен вмещать подпись шириной 160 |
| ширина подписи | `160` | wrap + fit-text, минимум 12 px |
| выноска | `длина 40`, `dash 6 4`, `1 px`, `#C4C5C4` | из архива |
| точка на конце выноски | `r = 2`, `#C4C5C4` | из архива |
| отступ подписи от выноски | `8` | — |
| линия оси | `2 px`, `#E4E9EB`, от центра первого до центра последнего | из архива |
| заливка кружка | `nodeFill` `#F3F4F6`; для точки с `title` и без `parentId` — `accent`-градиент | в архиве «активная» точка выделена градиентом |
| текст в кружке | `16 px`, semibold, `textPrimary` | метрика: ⌀56 вмещает до 4 цифр |
| canvas padding | `32`, между осью и подписями `40` | — |

Чередование: индекс 0 → подпись сверху, 1 → снизу, 2 → сверху… Если подписей больше 12 — шаг растёт
(`180 → 150% ширины подписи`), чтобы не слипались.

## 4. Рендер (`render/TimelineSvg.tsx`)

Слои снизу вверх: ось → выноски с точками → кружки с подписями → подписи точек (title + events).

- Текст в кружке центрируется, шрифт 16 semibold, при длине > 4 символов уменьшается до 12 (fit-text внутри круга: доступная область `0.7 ⌀`).
- Подпись точки: `title` 16 semibold `textPrimary`, `events` — 14 regular `textSecondary`, каждый на своей строке, ширина блока 160.
- Бейджи в flowchart-узлах: круг ⌀36, рамка 1 px (`accent` → `#4BD0A0`, `secondary` → `#0066FF`), заливка белая, текст 16 semibold того же цвета; позиция — слева внутри узла (`x + 12`, по центру по вертикали), текст узла сдвигается на `36 + 8 = 44`.
- `chevron`: полигон `M 0 0 L w−24 0 L w h/2 L w−24 h L 0 h L 24 h/2 Z`, текстовая область `0.75 w`.
- `secondary`: заливка `#DEE9FF`, текст `#27292D` (контраст 12.9:1).

## 5. Тесты и критерии приёмки

**Юнит-тесты (добавляются в существующие файлы):**
1. `parseTimeline`: секции → точки; `task` без `section`; `section [Имя]` → имя без скобок; хвостовые пробелы срезаны; несколько `events`; пустой `events`.
2. `normalizeTimeline`: label/title распределены верно, `laneId` проставлен.
3. `badge`: `"1. Понять проблему"` → `badge: "1"`, лейбл «Понять проблему»; `"1.5 млн"` → без бейджа; `"2022 год"` → без бейджа.
4. `layoutTimeline`: N точек → N кружков, шаг 180, чередование подписей, ширина холста = `2*padding + (n-1)*step + ⌀`.
5. `chevron`/`secondary` в `SHAPE_TO_ROLE` и в стилях ролей.
6. Снапшот IR для трёх таймлайнов из архива.

**Критерии приёмки:**
- [ ] Вставка `timeline` из mermaid не падает и рисуется: ось, кружки, чередующиеся подписи с выносками.
- [ ] `image (6)`, `image (14)`, `image (22)`, `image (24)` воспроизводятся по структуре (не пиксель-в-пиксель).
- [ ] `A[1. Понять проблему]` показывает кружок с «1» и текст рядом.
- [ ] `A>текст]` рисуется шевроном; `:::secondary` — синим.
- [ ] Экспорт PNG/SVG работает для таймлайна так же, как для flowchart.
- [ ] Все прежние 62 теста зелёные; `tsc` и `build` чистые.

## 7. Риски

| Риск | Митигация |
|---|---|
| `timeline` в mermaid отдаёт «сырой» текст с хвостовыми пробелами и скобками | покрыто тестами на нормализацию (§5.1) |
| У таймлайна нет `getTitle()` | берём регуляркой из `source`; если нет — без заголовка |
| Больше 12 точек → подписи слипаются | шаг растёт пропорционально; при >20 точках — предупреждение |
| Рефактор `DiagramIR` в объединение задевает layout/render/App | делаем на шаге 1 отдельным коммитом, тесты — страховка |
| Бейдж может «съесть» осмысленную нумерацию (`1.5 млн`) | регулярка требует пробел после точки + максимум 3 цифры |
