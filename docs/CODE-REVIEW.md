## 1. Баги

### HIGH — кнопки «Скачать» задизейблены после первой загрузки (исправлен)

`src/App.tsx`:

```ts
const ready = !!svgRef.current && parse.status === 'ok' && (!!layout || !!timelineLayout)
```

Реф **не триггерит перерисовку**: на рендере, где SVG монтируется, `svgRef.current` ещё `null`, а после монтирования нового рендера не происходит → кнопки остаются `disabled`, хотя схема видна.

**Доказательство (живой сайт):** после загрузки без единого взаимодействия `{ svg: true, buttons: disabled: true }`. То есть юзер открывает демо — и «Скачать PNG/SVG» выглядят выключенными, пока он не потрогает редактор. Мимо этого прошли все проверки, потому что я всегда взаимодействовал со страницей перед тестом.

**Фикс:** `const ready = parse.status === 'ok' && !!diagram` (состояние и мемо, а не реф). После фикса на свежей загрузке `disabled: false`.

**Вывод:** этот баг прошёл бы на e2e-тесте «открыл → кнопка активна»; юнит-тесты его не видят. Аргумент за добавление Playwright.

### MEDIUM — рёбра ищутся по совпадению индексов массивов (исправлен)

`src/diagram/render/DiagramSvg.tsx`:

```ts
edgeGeometry.map((edge, i) => { const irEdge = ir.edges[i]; ... })
```

`buildEdgeGeometries` сейчас кладёт элементы ровно в порядке `ir.edges`, поэтому индексы совпадают. Но это неявный контракт: стоит добавить фильтрацию/сортировку в геометрию — и рёбра «перекрасятся» на соседние (kind/arrow возьмутся от чужого ребра).

**Фикс:** `ir.edges.find((e) => e.id === edge.id)` + guard.

### LOW — `stripTags` не делает того, что написано в комментарии

`src/diagram/parse/label.ts`: комментарий «`<b>`, `<i>` переводим в начертание», а код просто удаляет теги — `<b>жирный</b>` станет обычным «жирный». Либо конвертировать в `bold`/`italic`-прогоны, либо поправить комментарий. (Markdown `**`/`*` работает.)

### LOW — `toSvgString` парсит viewBox без проверки

```ts
const [, , vbWidth, vbHeight] = viewBox.split(/\s+/).map(Number)
```

Если viewBox окажется не «4 числа» — в `width` уйдёт `NaN`. Сейчас viewBox всегда наш (4 значения), но защитный `?? fallback` стоит добавить.

### LOW — `downloadBlob`: `rel="noopener"` без `noreferrer`

Для blob-скачивания это безвредно, но по конвенции — `rel="noopener noreferrer"` (или убрать rel, это не `target="_blank"`).

### LOW — кэш измерителя растёт неограниченно

`src/diagram/measure/textMetrics.ts`: `cache = Map<key, number>`, ключ включает текст. При длительной работе с множеством уникальных строк кэш не чистится. На 1–2 тыс. узлов неважно; стоит ограничить (LRU или очистка при смене схемы).

### INFO — ложные предупреждения от `scanIgnored`

Регекспы `\bclassDef\b` / `class\s+...` срабатывают и на лейбле вроде `A[class of 2024]` — покажется предупреждение «стили игнорируются». Косметика.

## 3. Архитектура — оценка

**Хорошо:**
- Однонаправленный пайплайн `parse → normalize → measure → layout → render → export`, каждый слой без знания соседнего.
- DSL (`DiagramIR`) с версией + снапшот-тесты — защита от поломок mermaid.
- Вся тема в одном `theme.ts`; палитра, геометрия, правила отделены от компонентов.
- Чистые функции раскладки/переноса — легко тестировать без DOM.
- Разделение чистых (`useChatMessages`-стиль нет, но тут) — в целом логика оторвана от React.

**Что улучшить:**
1. **`any` от mermaid протекает.** `parseMermaid`/`normalize`/`layoutElk`/`normalizeTimeline` работают с `db: any`. Стоит ввести минимальный типизированный адаптер `MermaidDb { getVertices(): Map<...>; getEdges(); getSubGraphs(); getDirection(); getTasks() }`, чтобы `any` остался ровно в одном месте — на границе с библиотекой.
2. **Нет ESLint.** `tsc` ловит типы, но hook-правила (`exhaustive-deps`) не проверяются. В `ZoomPane` уже есть один `eslint-disable` — это ручной костыль вместо линтера. Добавить `eslint` + `react-hooks`-плагин.
3. **App.tsx 355 строк** — кандидат на `EditorPane`/`PreviewPane`. Не блокер.
4. **Нет e2e.** Именно отсутствие e2e пропустило HIGH-баг с кнопками в прод. Playwright («открыл → кнопка активна → скачал PNG» + скриншот-снапшоты) — следующий приоритет.

## 4. Синтаксис и стиль — мелочи

- `let m: RegExpExecArray | null` в цикле `while` — можно `const` внутри условия (косметика).
- Смесь inline-стилей и CSS-классов в `App` — читаемо, но часть (кнопка `btnStyle`, селекты) просится в `app.css`.
- `btnStyle()` создаёт новый объект на каждый рендер — на этом масштабе неважно.
- `toArray<T>` с `as T[]` — приемлемо как часть адаптера mermaid (см. §3.1).
- `plural()` не покрыта тестами (косметическая функция).
