# Проблематика проекта: с чем столкнулись и как решали

Хронология честная: половина пунктов — это ошибки, которые я сам допустил и потом чинил.
Формат: **проблема → как проявлялась → решение → что осталось**.

---

## 1. Постановка задачи

| Проблема | Проявление | Решение |
|---|---|---|
| «Сделать аналог `mermaid.ai`» | `mermaid.ai` — официальный сайт Mermaid с AI-генерацией схем, там редактор + чат + экспорт + шаринг. В контексте же описан только «вставил текст → получил картинку» | Делаем ровно по контексту: textarea, превью, скачивание. AI/шаринга/истории нет. Риск: ожидание «как у них» шире нашего объёма |
| «Дизайн как в архиве» | В архиве 25 слайдов, из них только ~8 — блок-схемы. Остальное таймлайны, пирамида, венн, сетки, просто слайды с текстом | Разобрали все 25 по файлам (`docs/COVERAGE.md`), приоритизировали по эффекту: сначала таймлайны (8 слайдов), потом бейджи |
| «Без памяти» | Неясно, запрещены ли `localStorage`, история, undo, автосохранение | Трактуем строго: состояние живёт только в `useState`. Проверено grep-ом — ни `localStorage`, ни `sessionStorage`, ни cookie |
| «Юзеру нельзя менять стили» | Если стили нельзя менять из разметки, как тогда пометить «важный» узел? | `classDef`/`style`/`linkStyle`/`click`/`%%{init}%%` игнорируются с предупреждением; вид меняют только маркеры `:::accent`, `:::secondary`, `:::outline`, `:::muted` — то есть 4 предопределённых состояния, а не произвольный CSS |
| Мобильная версия | В ТЗ её не было; выяснилось при демонстрации | `@media (max-width: 900px)` → «башенка»: ввод сверху, вывод снизу |

## 2. Данные: архив противоречит сам себе

| Проблема | Проявление | Решение |
|---|---|---|
| Три визуальных семейства | A: мягкие заливки + ортогональные стрелки (10 слайдов). B: белые карточки с **чёрной** рамкой + **безье**-стрелки (4 слайда). C: пастельные градиенты | Канонизировали **A**: она доминирует и читается как брендовая инфографика. B отвергли — чёрные рамки и кривые стрелки плохо ложатся на автогенерацию |
| 4 разных зелёных | Пиксельные гистограммы: `#39D3AD`, `#35CBAA`, `#3DD8B0`, `#47C397` — в одном архиве | Один брендовый `#4BD0A0` из `vars.sass` проекта Нетологии |
| 3 разных серых заливки | `#F2F4F6`, `#F2F3F6`, `#F3F3F6` | Один `#F3F4F7` (это `$c-light-grey` из `vars.sass`) |
| Серые стрелки вместо зелёных | Я поставил связям `#9FA3A7`, заказчик: «есть зелёный блок, а зелёной стрелки нет» | Замерил архив: `#47C397` (image 25), `#31C2A7` (image 3) → все связи зелёные. **Моя ошибка**, исправлена |
| «Человеческий фактор»: подписи где попало, разнобой размеров | Схемы делали руками, правили в разных редакторах | Ввели правила: сетка 8 px, радиус 12, линия 2 px, наконечник 8 px, паддинги, минимальный шрифт. Часть правил помечена как «придумано нами», а не «есть в архиве» |
| Слайд `image (9)` — вообще не схема | Код-блок и текст | Вне scope, отмечено как ➖ |

**Как разбирались с данными:** написал свой PNG-декодер и утилиты (гистограммы, кропы с увеличением 4–6×, сканер строк). Все утверждения о цветах и геометрии — из замеров, а не «на глаз»: например, ⌀ кружка таймлайна 71 px при шаге 154 px на слайде 960 px.

## 3. Технические проблемы

### 3.1 Mermaid как источник модели

| Проблема | Проявление | Решение |
|---|---|---|
| `mermaid.db` — **внутренний** API, не контракт | `getVertices()` в v12 вернул `Map`, а не объект; форма может поменяться в любом мажоре | Версия закреплена (`12.2.0`), вся модель нормализуется в наш `DiagramIR`, есть снапшот-тесты — при апдейте падение будет сразу и понятно где |
| `labelType: 'text'` vs `'string'` | В простом режиме перенос строки приходит **литерально** как `\n` (два символа), в markdown — как `<br>` | Нормализатор обрабатывает оба случая + HTML-entity + вырезание неподдерживаемых тегов |
| `timeline` отдаёт «грязный» текст | `task: "Рост "` с хвостовым пробелом; `section [Первый этап]` приходит **со скобками**; метода `getTitle()` нет вообще | `trim()`, срезание скобок, `title` берём регуляркой из исходника. Покрыто тестами |
| Вес библиотеки | `mermaid.min.js` — 1.5 МБ gzip, если тянуть целиком | Используем вход `mermaid.core.mjs` (13 КБ gzip) + ленивые чанки; чанк flowchart ≈ 150 КБ gzip |

### 3.2 ELK (раскладка)

| Проблема | Проявление | Решение |
|---|---|---|
| Разрыв циклов ломал слои | В примере из ТЗ узел `D` уезжал в **первый** ряд рядом с `A`: `A@12 B@88 C@164 D@12`. Картинка не совпадала с ожидаемой | Прогнал 5 стратегий разрыва циклов и сравнил координаты: `default/GREEDY` — плохо, `MODEL_ORDER/DEPTH_FIRST` — правильно. Включил `MODEL_ORDER` |
| Координаты в иерархии | С `hierarchyHandling: INCLUDE_CHILDREN` дети кластера приходят **в его координатах**, а рёбра — в координатах **ближайшего общего предка** концов. Наивное сложение давало съехавшие стрелки | Приводим всё к абсолютным: узлам прибавляем позицию кластера, рёбрам — позицию LCA |
| Троттлинг таймеров | В **фоновой** вкладке Chrome раскладка занимала «2 секунды», тесты выглядели медленными | ELK в bundled-сборке использует `setTimeout`-шим. Проверил: в активной вкладке 3–5 мс. Это артефакт измерения, не проблема кода |
| Вес ELK | `elk.bundled.js` — 1.5 МБ raw / **454 КБ gzip**, тяжелее самого mermaid | Принято осознанно: без ELK нет ортогональных рёбер, а это ядро стиля. Кандидат на оптимизацию (worker-версия, ленивый импорт) |

### 3.3 Экспорт изображения

| Проблема | Проявление | Решение |
|---|---|---|
| Шрифты не видны при растеризации | SVG, загруженный в `<img>` для canvas, изолирован: шрифты страницы недоступны → текст молча подменялся фолбэком, метрики «ехали» | Вшиваем `@font-face` с base64 (4 начертания ≈ 160 КБ) прямо в SVG |
| Проверка «а будет ли в Safari?» | Автоматизировать клик по кнопке в Safari не мог | Прогнал экспортированный SVG через **WebKit** (`qlmanage` — тот же движок): текст отрендерился родным SB Sans Text. Риск в основном снят, финальный клик — за человеком |
| Прозрачный фон | Просто «не заливать canvas» недостаточно: в SVG была белая подложка | `<rect id="canvas-bg">` удаляется из клона при `transparent: true`; проверил alpha=0 в углу итогового PNG |

### 3.4 Деплой

| Проблема | Проявление | Решение |
|---|---|---|
| Абсолютные пути к шрифтам | `/fonts/...` на GitHub Pages (`/<repo>/`) дал бы 404 | Шрифты переехали в `src/theme/fonts` и подключаются через `?url` — Vite подставляет `base` |
| `base` под подпапку | Сайт живёт в `/mermaid/` | `base: process.env.VITE_BASE`, в workflow `VITE_BASE=/<repo>/` |
| Приватный репозиторий | `pages API → 404`; `configure-pages` падал с невнятной ошибкой. Pages для приватных репо требует платного плана | Репозиторий сделали публичным. Плюс убрали `enablement: true` — включать Pages может только человек с админскими правами, `GITHUB_TOKEN` этого не может |
| `npm ci` в CI | Нужен `package-lock.json` | Он в репозитории, шаг проходит |

## 4. Дизайн и UX

| Проблема | Проявление | Решение |
|---|---|---|
| **Fit-text** — главное требование | Mermaid растягивает блок под текст; нужно наоборот | Блоки ограничены 260×132; шрифт подбирается бинарным поиском 18→11 px; в пределе — «…». Проверено: 380 символов → 11 px, бокс не вырос |
| Текст в ромбе вылезал за скосы | Ромб — не прямоугольник, текстовая область меньше | Вписанный прямоугольник `0.60 w × 0.50 h`; для круга `0.70 d`; для шестиугольника `0.75 w` |
| **Контраст** | В архиве белый текст на мятном `#4BD0A0` — это **1.80 : 1**, нечитаемо | Считаем контраст, а не «на глаз»: в акцентных узлах тёмный текст (`7.51 : 1`); зелёный текст — `#2B8A64` (4.27 : 1) |
| Оценка ширины текста врала | Моя эвристика по классам символов ошибалась на **10–20 %** — в тестах переносы не совпадали с реальностью | Замерил ширины символов поштучно на SB Sans Text и сделал таблицу per-mille: расхождение ≤2 % на связном тексте. В браузере вообще используется `canvas.measureText` |
| Подписи рёбер наезжали | Ложились на блоки и друг на друга; ширина подложки считалась «длина строки × 0.55» | Ширина по реальным метрикам; подпись ставится на первый сегмент, свободный от узлов и других подписей |
| Параллельные рёбра | `A→B` и `B→A` рисовались одной линией | Развод на 12 px перпендикулярно направлению |
| Таймлайн: крайняя подпись обрезалась | `label.x = cx − 80` уходило в минус | Боковой отступ `max(32, labelWidth/2)` |
| **`maxWidth: 100%` на `<svg>` ломал зум** | SVG сначала сжимался под контейнер, потом масштабировался → зум 27 % вместо 52 %, содержимое уезжало за кадр | Убрал подгонку из CSS: размерами управляет только `ZoomPane` |
| Смена примера не сбрасывала вид | После ручного зума новая схема открывалась в чужом масштабе | `contentKey` у `ZoomPane`: новая схема → «вписать» |
| Замороженные CSS-переходы | Кнопки «показывали» `opacity: 0.4` и выглядели выключенными; я чуть не начал чинить несуществующий баг | В фоновой вкладке Chrome переходы не анимируются. Проверка: `transition: none` → opacity сразу 1. Вывод: не доверять замерам в невидимой вкладке |

## 5. Процессные проблемы (мои)

| Проблема | Проявление | Вывод |
|---|---|---|
| **Неверный порядок этапов** | Сделал парсинг, метрики, fit-text — но картинки в браузере не было, и заказчик справедливо написал «не вижу изменений» | Доводить до **видимого** результата раньше: сначала «текст → картинка», потом внутренняя чистота |
| Выдавал предположения за факты | Дважды: «стрелки серые» и «оценка ширины ±5 %». Оба опровергнуты замерами | Сначала проверка, потом утверждение; в документах помечаю `[ПРОВЕРЕНО]` / `[ПРИДУМАНО]` / `[НЕ ПРОВЕРЕНО]` |
| Слепое доверие README библиотеки | Написал `[ПРОВЕРЕНО]` про синхронный ELK, хотя читал только README `beautiful-mermaid` | Пометку снял; «прочитал» ≠ «запустил» |
| Ищем не там, где проблема | Долго искал токены Нетологии в `node_modules`, тогда как брендовый цвет лежал в `apps/landings/src/stylesheets/vars.sass` | Сначала искать в коде продукта, потом в зависимостях |

## 6. Что осталось и какие риски

| Риск / долг | Комментарий |
|---|---|
| 4 слайда не поддерживаются | Пирамида (7), «змейка» (15), карта профессии со сеткой и списками (16), упражнение с перекрещивающимися безье-стрелками (18). Каждый тянет отдельный тип визуализации |
| Лицензия шрифта | SB Sans Text скачан с CDN Сбера. Лендинги Нетологии его используют, но хранение копии в репозитории стоит согласовать с владельцем бренда |
| Вес бандла | ~681 КБ gzip (ELK + mermaid + React). Для внутренней тулзы приемлемо, для публичной страницы — кандидат на оптимизацию |
| Нет e2e | Юнит-тестов 89, но рендер проверяется глазами. Playwright со скриншот-снапшотами и проверкой скачивания файла — следующий шаг для CI |
| Нет тестов на визуал | Геометрия (раскладка, габариты, подписи) покрыта, а «как это выглядит» — нет |
| Стили только светлые | Тёмная тема не делалась и ТЗ не требует |
